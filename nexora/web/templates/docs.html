Documentation

How to install Nexora, connect it to Discord and configure each system.

Installing on Windows

  1. Install Python 3.12 or newer. Tick Add python.exe to PATH in the installer.
  2. Download or clone the Nexlify repository and open the folder.
  3. Double-click install.bat. It creates a virtual environment, installs packages and creates .env with a random session secret.
  4. Fill in .env (see below), then double-click start.bat. The bot and website start together at http://localhost:8000.

Creating the Discord application

  1. Open the Discord Developer Portal and create an application.
  2. Bot tab: reset and copy the token into DISCORD_BOT_TOKEN. Turn on Server Members Intent and Message Content Intent. Logging, welcome messages, automod and leveling depend on them.
  3. OAuth2 tab: copy the Client ID and Client Secret into DISCORD_CLIENT_ID and DISCORD_CLIENT_SECRET.
  4. Still under OAuth2, add the redirect http://localhost:8000/auth/callback. It must exactly match DISCORD_REDIRECT_URI.
  5. Put your own Discord user ID in BOT_OWNER_IDS to unlock the System page (backups, errors, diagnostics).
  6. Optional: set DEV_GUILD_ID to a test server's ID so slash commands appear there instantly. Global commands can take up to an hour.

Permissions and role position

The invite link asks for Administrator to keep setup simple. If you prefer fewer permissions, Nexora needs Manage Roles, Manage Channels, Kick, Ban, Moderate Members, Manage Messages, View Audit Log, Manage Server (to read invites) and Embed Links. Drag Nexora's role above any role it should assign or moderate. Discord won't let a bot manage roles above its own.

Who can use the dashboard

Anyone with Manage Server can manage that server's dashboard. Under Server Settings you can give extra roles full or read-only access. Each moderation action from the dashboard also checks your own Discord permissions, so a dashboard user without Ban Members can't ban.

Logging

Every category (messages, members, roles, channels, moderation, voice, server) can be switched on or off and sent to its own channel. All events are stored for the retention period you choose and are searchable on the Logs page.

Some details are limited by Discord itself:

  • Content of edited or deleted messages is only known if the message was sent while Nexora was running (it keeps the last 5,000 messages in memory).
  • Discord's audit log only records who deleted a message when it was someone other than the author, and it groups repeated deletions. When Nexora can't know who did something, the log says so.
  • Attachments on deleted messages are removed from Discord's servers, so only their names and sizes are logged.

Placeholders

Welcome, goodbye, level-up, ticket, application, custom command and automation messages can use:

{user} {user.name} {user.display_name} {user.id} {user.avatar} {server} {member_count} {member_count_ordinal}. Level-ups also have {level} and {xp}; custom commands have {args} and {channel}; automations can use {role}, {level} and {form} depending on the trigger.

Tickets

Create a panel on the Tickets page, choose its channel, category and staff roles, add up to five questions, then press Publish. Members click the button, answer the questions, and get a private channel. Staff can claim, transfer, set priority and close. Closing saves an HTML transcript to the dashboard and optionally to a transcript channel and the member's DMs.

Applications

Forms can have any number of questions. Text questions are grouped five at a time (Discord's limit per pop-up) and multiple-choice questions appear as dropdowns, so long forms run over a few steps. Submissions go to a review channel and the Applications page. With required votes above one, that many reviewers must agree before the decision is applied.

Automations

An automation is a trigger, optional conditions and one or more actions. Example: when a member reaches level 10 and doesn't have the Regular role, give them the role and post a message in #general. Each run is recorded with its result, and failing actions are shown with the reason.

Backups

Per-server configuration can be exported and imported from Server Settings. Bot owners can make and restore full database backups from the System page. Restoring always makes a safety copy first. Backups are stored in data/backups.

Updating

Run update.bat (or git pull then install.bat). Database migrations run automatically at startup, and your data and .env are kept.

Moving to PostgreSQL later

All queries go through nexora/db with parameter binding, and the schema is plain SQL in nexora/db/migrations. A PostgreSQL port means swapping the connection layer for asyncpg and converting the AUTOINCREMENT columns.
